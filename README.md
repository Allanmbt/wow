# 魔兽世界 Q/E/V 战斗助手

当前提供 Q 圣印、E 神圣打击/审判、V 中毒净化，以及可选的 **bag.jpg 指针自动拾取**。战斗结束、无目标或技能多次未成功都不会结束运行，由上侧键手动停止。旧 R、血条/经验死亡判断与旧的定时拾取流程已移除。怪物名称 OCR 单独保留，不参与攻击。

## 启动

关闭旧工具窗口，再运行；原虚拟环境与依赖可继续用：

~~~powershell
cd D:\github\wow
.\.venv\Scripts\python.exe monster_ocr.py
~~~

也可运行同目录的 auto_combat.py。只开一个实例。

- 鼠标上侧键 XButton2：开启/关闭本轮攻击，不改变独立的拾取勾选。
- F10 或“停止全部”：停止攻击和拾取，并取消拾取勾选。
- “3 秒后开启”：点击后切回游戏。
- 切出游戏时 Q/E/V 暂停发键，保持已开启；切回绑定游戏后自动继续。
- 红字停攻选项已移除。F10、“停止全部”、关闭程序和配置校验操作仍可停止；截图或输入系统异常会提示错误。

工具绑定开启瞬间的前台窗口，请在游戏中开启。关闭聊天输入栏，提前选好怪物。工具不选怪、不移动、不追击，不读取游戏内存或修改客户端。

## 指针自动拾取（默认关闭）

默认使用项目根目录的 **bag.jpg**，通过系统指针匹配和鼠标附近的画面备用识别两条路径工作。学习指针采集功能已取消，不再读取之前保存的学习样本。

勾选“自动拾取”即可：

1. 如果本次运行已经通过侧键绑定过游戏，直接复用该窗口。
2. 尚未绑定时，勾选后在 **3 秒内切回游戏**，只开启拾取监测，不启动 Q/E。也可在游戏内按侧键启动攻击，同时绑定拾取。
3. 将鼠标移到可拾取尸体上。程序通过 [GetCursorInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorinfo)、[GetIconInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-geticoninfo) 和 [DrawIconEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-drawiconex) 读取、绘制当前指针到内存；使用当前指针的不透明区域在 bag.jpg 中匹配，忽略指针外的截图背景，并适配一定的尺寸差异。
4. 系统指针或画面路径匹配度达到 **50%（包含 50%）**，且鼠标稳定约 0.15 秒后，在当前位置右键一次，不移动鼠标。点击前再确认指针仍匹配、鼠标仍位于绑定的游戏窗口，且没有按住其他鼠标键或 Ctrl/Shift/Alt/Win。
5. 持续显示同一个袋子指针不会重复点击。移开至少约 0.4 秒再移回可再次触发，另有约 1 秒的点击保护。边移动边悬停时会等鼠标稳定。

**拾取与攻击是独立线程和开关。** 用侧键停止 Q/E/V 后，拾取仍可继续。取消“自动拾取”立即停止指针监测和后续点击，不会修改 Q/E/V 配置；F10 随时停止全部。程序关闭时所有线程停止。保存过的拾取勾选会加载，但重启后需按侧键绑定游戏，或取消后重新勾选，以免自动绑定其他窗口。

请在游戏内开启“自动拾取”，否则右键可能只打开拾取窗口。走近尸体、把鼠标指向尸体由你完成；程序不按死亡时间或固定坐标点击。bag.jpg 缺失、不可读或原生指针读取失败时会显示提示并关闭拾取，不中断攻击。更换 bag.jpg 后取消再勾选即可重新加载。

系统指针匹配失败或 Windows 指针不可见时，会尝试识别鼠标附近约 204×204 像素的游戏画面。备用识别只比较 bag.jpg 中袋子与箭头的棕黄色纹理，忽略绿色背景；命中位置必须靠近鼠标，不会全屏寻找背包图标。点击前复查局部图案仍在、鼠标仍在原位置；截图和图像计算都在键鼠共用锁外执行。画面中若也不包含指针，备用路径同样无法识别，不会强制右键。

界面显示系统指针相似度、画面备用扫描/命中、右键暂缓等状态。56% 已满足识别条件；鼠标稳定约 0.15 秒且点击前复核通过后，原地右键一次。修改代码后需关闭旧进程重新启动，取消再勾选只能重新加载图片。

## E 更顺畅的触发规则

1. 神圣打击与审判都就绪时，开启一个最多 4 次的短连发：松开后约 0.18 秒补下一次 E，实际两次按下通常约 0.2 秒，随系统调度变化。
2. 每次补发前都读取最新图标；已经进入冷却的技能不再作为补发依据。两者都冷却或画面未知，马上停止这轮连发。
3. 只有一个技能就绪时按一次 E；之后哪个恢复就绪就用哪个，不按固定周期刷 E。
4. 短暂公共冷却结束、图标重新就绪后可及时补 E；图标始终没变化的失败施放才间隔至少 2 秒重试，不因无目标或失败次数自动停攻。
5. 正常冷却确认仍保留神圣打击 10 秒、审判 8 秒的保护与图标校验。Q 继续按圣印图标补，不参与 E 连发。

一个 E 能否同时放出两个技能由游戏内键位和公共冷却决定；工具通过短连发尽量及时补出剩下的技能，不能绕过游戏自身的施放限制。请保留你原来能使用两个技能的 E 绑定。

## V 中毒净化：首次校验后复用

已将提供的两张图片裁出图标主体，保存为 `poison_1.png` 和 `poison_2.png`。倒计时文字不参与模板比较。

1. 让自己处于上述任一种中毒状态，点击 **“校验减益栏 · V”**，框选自己整排减益图标。两种毒不需要同时出现，不要框选技能栏或整个屏幕。
2. 必须实际匹配到其中一种图标才保存检测区域和图标尺寸；校验失败保留之前的有效配置。
3. 成功后保存到 `combat_config.json`，重启后直接复用。减益图标在该区域内换位置仍可识别；移动减益栏或改变 UI 缩放后重新校验。
4. 上侧键开启战斗后，每约 0.1 秒检查一次；发现任一种中毒即优先发送 **V**，随后让出约 1.5 秒公共冷却，再继续 Q/E。
5. V 发出后继续观察图标。图标连续消失至少 0.25 秒后记录已确认解除；仍中毒时每隔至少 1.6 秒复查重试，不刷屏连按。工具确认的是图标消失，未读取游戏内存。

请确保你的 V 绑定会对自己施放纯净术（按你已有的自身施法/宏配置）。工具只按 V，不改变施法目标或鼠标位置。未校验减益栏时不发送 V，原 Q/E 和拾取仍可运行。

扩展其他中毒图标时可在 `poison_monitor.py` 的 `POISON_TEMPLATES` 中追加图标文件；无需修改 Q/E 策略。识别使用纹理和颜色，纯绿色色块不会当作中毒。

界面主状态用绿色强调，净化提示用琥珀色，拾取与设置说明使用灰色；只展示计数和必要状态。

首次没有位置，或者移动了技能栏，才用三个“定位”按钮框选一次。定位会同时保存图片与 combat_config.json 中的屏幕坐标。**本地图片只描述图标长相，单靠它不能知道屏幕坐标**；本版不会自动全屏搜索技能位置。不要把整条技能栏、鼠标悬停高亮或冷却中的图标保存成就绪样本。

新配置保存独立的 cursor_loot 拾取开关、圣印匹配阈值、三个技能区域和中毒减益栏校验区域/尺寸；旧 stop_on_error 配置会移除；旧版 R/血条/经验/定时拾取配置会在加载时移除，原技能图片不删。遗留的 R 图片不再被任何逻辑读取。

## 安装（尚无虚拟环境时）

本机 Python 3.14 已验证。无需激活虚拟环境：

~~~powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

EasyOCR/PyTorch 体积较大。首次模型下载后复用用户目录中的 .EasyOCR 缓存。战斗截图和图标比较使用 MSS/OpenCV；主战斗流程不再加载红字 OCR。

## 保留的名称识别

~~~powershell
.\.venv\Scripts\python.exe monster_ocr.py --ocr
~~~

名称识别模式与攻击分别启动。旧名称识别区域和目标保存在 config.json，不会触发攻击。
