# 魔兽世界 Q/E/R/V 战斗助手

提供可独立勾选的自动战斗、自动拾取和自动采矿。战斗包含 Q 圣印、R 制裁、E 审判/神圣打击和 V 净化，怪物名称 OCR 单独运行。

## 启动

关闭旧工具窗口，再运行；原虚拟环境与依赖可继续用：

~~~powershell
cd D:\github\wow
.\.venv-local\Scripts\python.exe monster_ocr.py
~~~

也可运行同目录的 auto_combat.py。只开一个实例。

- 单按鼠标左侧上键（鼠标 5）或实体键盘的 F10，开启已勾选的功能。再按任一开关即可停止全部。停止后保留勾选。
- “停止全部”按钮也可停止战斗、拾取和采矿。
- “3 秒后开启”：点击后切回游戏。
- 切出游戏时键盘和鼠标输出暂停，保持已开启；切回绑定游戏后自动继续。
- 鼠标 5 或 F10、“停止全部”、关闭程序和配置校验操作均可停止；截图或输入系统异常会提示错误。

工具会在收到开启指令后最多等待 2 秒，确认游戏前台窗口稳定约 0.1 秒后绑定。等待期间再按任一开关或点击“停止全部”可取消。请在游戏中开启，关闭聊天输入栏并提前选好怪物。

## USB HID 键鼠输出

自动功能的键盘和鼠标由 [input_output.py](input_output.py) 统一通过 CH9329 输出。项目的 [input_config.json](input_config.json) 指定 COM3、9600 和地址 0x00。启动后界面会显示两个后端。

### CH9329F + CH343 串口转 USB HID

Windows 的“端口 (COM 和 LPT)”应出现 `USB-SERIAL CH343`，接收键鼠操作的电脑也要连接板子的 HID 端。两端可接到同一台电脑。串口监听工具和芯片配置工具须先释放该 COM 口。下面以本机检测到的 `COM3` 为例。

~~~powershell
.\.venv-local\Scripts\python.exe -m pip install pyserial
.\.venv-local\Scripts\python.exe input_check.py --list-ports
.\.venv-local\Scripts\python.exe input_check.py --ch9329 COM3 --probe --trace
~~~

`--probe` 只读取设备信息与配置。模式 `0x80` 支持键盘及相对鼠标。拾取和采矿的右键共用 COM3，通过 CH9329 发送按下、松开报告，鼠标位置不动。芯片错误会显示在对应功能的状态行。

启动命令见上文。端口变更时可编辑 `input_config.json`，或用环境变量 `CH9329_PORT` 临时覆盖。检查串口前先关闭使用 COM3 的助手或串口调试工具。

- 串口能打开但没有有效应答时，确认板子处于 **协议传输模式**。默认设置是 **9600 / 8N1 / 地址 0x00**。如果已用厂商工具改成 115200，自检命令加 `--baud 115200`，主界面使用 `$env:CH9329_BAUD = "115200"`。自定义地址对应 `--address 0xNN` 或 `CH9329_ADDRESS`。
- 有芯片应答但 USB 未枚举时，检查 HID 端的数据线。芯片应答正常而目标没有反应时，核对 HID 接收端和前台焦点。
- [ch9329_output.py](ch9329_output.py) 封装了 `CH9329Keyboard`。调用方可把实例传给 `WindowsInput(keyboard=...)`，复用前台窗口检查和 `send()`，结束时调用 `close()`。所用报文与 [按键编码](docs/按键编码.txt) 和 [串口通信协议](docs/CH9329芯片串口通信协议.pdf) 对照，初始化查询不会写入芯片配置。

Pico 的键盘桥仍可供代码独立调用。主界面的自动功能要求 CH9329 键鼠设备。

## 战斗开关和技能配置排查

Windows 直接监听实体鼠标 5 和 F10 按下再松开的事件。开关无需 CH9329 或 COM3 参与，自动技能键和点击仍通过 CH9329。独立的 `diagnose_ctrl.py` 可只读排查鼠标 5 或 F10、前台窗口和技能配置。

不同技能框选到同一格时会明确报错，拒绝覆盖原图片和配置；启动时也会检查已保存坐标，防止错误配置持续发 Q。圣印应选第二格，神圣打击选第一格，审判选第四格；框选范围不要包含相邻图标。底部诊断显示技能状态/相似度及修饰键占用，窗口按字体和 DPI 预留显示空间。

## 悬停拾取与采矿

- **自动拾取**使用原分辨率视频提取的 [袋子模板](loot_cursor.png)。指针稳定约 150 毫秒、点击前复核通过后，在当前位置右键一次。移开袋子指针约 0.4 秒，或移动超过 24 像素，可开始下一次悬停。拾取仍有 1 秒点击间隔保护。
- **自动采矿**使用原分辨率视频提取的 [矿镐模板](mining_cursor.png)。识别到矿镐时暂停 Q/E/R。指针稳定后右键一次，随后每隔至少 4 秒复核并右键一次。矿镐消失后停止复点，持续约 0.4 秒后恢复攻击。V 净化照常运行。
- 程序先识别 Windows 系统指针，然后尝试鼠标附近的画面。透明模板只比较图案像素。系统指针分数的最低门槛为 50%，画面模板为 65%，并同时检查颜色。窗口焦点、鼠标位置、按键占用和点击前复核也会影响是否发送。
- 状态行会区分等待稳定、画面命中和右键暂缓。成功发送后，控制台会显示实际使用的鼠标后端。需要只采矿时，勾选“自动采矿”并取消其余两项，再按鼠标 5 或 F10。

## R 制裁

在游戏里把制裁绑到 R，等图标就绪且没有倒计时，再点助手的「制裁 (R)」框选完整图标。校验成功会保存图片和坐标。制裁就绪时优先发送 R，优先级高于审判和神圣打击。制裁在冷却或图标无法确认时，继续执行原来的 E 攻击规则。还没校验制裁时可照常使用原有技能。

## E 更顺畅的触发规则

战斗技能栏的目标采样间隔为 25 毫秒。相邻的三个技能图标共用一张截图；相距较远或跨显示器时分别截图。

1. 神圣打击与审判都就绪时，开启一个最多 4 次的短连发：松开后约 0.18 秒补下一次 E，实际两次按下通常约 0.2 秒，随系统调度变化。
2. 每次补发前都读取最新图标；已经进入冷却的技能不再作为补发依据。两者都冷却或画面未知，马上停止这轮连发。
3. 只有一个技能就绪时按一次 E；之后哪个恢复就绪就用哪个，不按固定周期刷 E。
4. 短暂公共冷却结束、图标重新就绪后可及时补 E；图标始终没变化的失败施放才间隔至少 2 秒重试，不因无目标或失败次数自动停攻。
5. 正常冷却确认仍保留神圣打击 10 秒、审判 8 秒的保护与图标校验。Q 继续按圣印图标补，不参与 E 连发。

一个 E 能否同时放出两个技能由游戏内键位和公共冷却决定；工具通过短连发尽量及时补出剩下的技能，不能绕过游戏自身的施放限制。请保留你原来能使用两个技能的 E 绑定。

## V 中毒净化：首次校验后复用

已将提供的两张图片裁出图标主体，保存为 `poison_1.png` 和 `poison_2.png`。倒计时文字不参与模板比较。

1. 让自己处于上述任一种中毒状态，点击 **“校验减益栏 · V”**，框选自己整排减益图标。两种毒不需要同时出现，不要框选技能栏或整个屏幕。
2. 必须实际匹配到其中一种图标才保存检测区域和图标尺寸；校验失败保留之前的有效配置。
3. 成功后保存到 `combat_config.json`，重启后直接复用。减益图标在该区域内换位置仍可识别；移动减益栏或改变 UI 缩放后重新校验。
4. 开启战斗后，目标检查间隔为 50 毫秒；发现任一种中毒即优先发送 **V**，随后让出约 1.5 秒公共冷却，再继续战斗。
5. V 发出后继续观察图标。图标连续消失至少 0.25 秒后记录已确认解除；仍中毒时每隔至少 1.6 秒复查重试，不刷屏连按。工具确认的是图标消失，未读取游戏内存。

请确保你的 V 绑定会对自己施放纯净术（按你已有的自身施法/宏配置）。工具只按 V，不改变施法目标或鼠标位置。未校验减益栏时不发送 V，原 Q/E 和拾取仍可运行。

扩展其他中毒图标时可在 `poison_monitor.py` 的 `POISON_TEMPLATES` 中追加图标文件；无需修改 Q/E 策略。识别使用纹理和颜色，纯绿色色块不会当作中毒。

界面主状态用绿色强调，净化提示用琥珀色，拾取与设置说明使用灰色；只展示计数和必要状态。

| 文件 | 应保存的状态 |
| --- | --- |
| seal_ready.png | 第二个图标，圣印未开启、无倒计时 |
| strike_ready.png | 第一个图标，神圣打击就绪、无倒计时 |
| judgment_ready.png | 第四个图标，审判就绪、无倒计时 |
| sanction_ready.png | 制裁就绪、无倒计时 |

原有图片和三处坐标继续使用，不需要每次重新框选。你也可以自己截取完整图标，保存/替换为以上文件名，重启后加载；应保持相同 UI 布局与缩放。

首次没有位置，或者移动了技能栏，才用三个“定位”按钮框选一次。定位会同时保存图片与 combat_config.json 中的屏幕坐标。**本地图片只描述图标长相，单靠它不能知道屏幕坐标**；本版不会自动全屏搜索技能位置。不要把整条技能栏、鼠标悬停高亮或冷却中的图标保存成就绪样本。

配置保存功能勾选、圣印匹配阈值、技能区域和减益栏的位置与尺寸。

## 安装（尚无虚拟环境时）

本机 Python 3.14 已验证。无需激活虚拟环境：

~~~powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

EasyOCR/PyTorch 体积较大。首次模型下载后复用用户目录中的 .EasyOCR 缓存。战斗截图和图标比较使用 MSS/OpenCV；主战斗流程不再加载红字 OCR。

## 保留的名称识别

~~~powershell
.\.venv\Scripts\python.exe monster_ocr.py --ocr
~~~

名称识别模式与攻击分别启动。旧名称识别区域和目标保存在 config.json，不会触发攻击。
