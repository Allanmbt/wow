# 魔兽世界 Q/E/R/V 战斗助手

提供可独立勾选的自动战斗、自动拾取和自动采矿。战斗包含 Q 圣印、R 制裁、E 审判/神圣打击和 V 净化，怪物名称 OCR 单独运行。

## 启动

关闭旧工具窗口，再运行；原虚拟环境与依赖可继续用：

~~~powershell
cd D:\github\wow
.\.venv-local\Scripts\python.exe monster_ocr.py
~~~

也可运行同目录的 auto_combat.py。只开一个实例。

- 单按鼠标左侧上键（鼠标 5）或实体键盘的 F10，开启已勾选的功能。再按任一开关即可停止全部。停止后保留勾选。
- “停止全部”按钮也可停止战斗、拾取和采矿。
- “3 秒后开启”：点击后切回游戏。
- 切出游戏时键盘和鼠标输出暂停，保持已开启；切回绑定游戏后自动继续。
- 鼠标 5 或 F10、“停止全部”、关闭程序和配置校验操作均可停止；截图或输入系统异常会提示错误。

工具会在收到开启指令后最多等待 2 秒，确认游戏前台窗口稳定约 0.1 秒后绑定。等待期间再按任一开关或点击“停止全部”可取消。请在游戏中开启，关闭聊天输入栏并提前选好怪物。

## USB HID 键鼠输出

自动功能的键盘和鼠标由 [Windows 输入模块](wow_assistant/device/windows.py) 统一通过 CH9329 输出。[input_config.json](config/input_config.json) 默认自动识别唯一的 CH343 串口，使用 9600 和地址 0x00。旧电脑的 COM3 和新电脑的 COM7 可共用这一份配置。

### CH9329F + CH343 串口转 USB HID

Windows 的“端口 (COM 和 LPT)”应出现 `USB-SERIAL CH343`，接收键鼠操作的电脑也要连接板子的 HID 端。两端可接到同一台电脑。测试前请关闭助手及占用串口的配置或监听工具。

~~~powershell
.\.venv-local\Scripts\python.exe -m pip install pyserial==3.5
.\.venv-local\Scripts\python.exe input_check.py --list-ports
.\.venv-local\Scripts\python.exe input_check.py --probe --trace
~~~

`--probe` 显示实际选中的 COM 口，并读取芯片信息和 USB 枚举状态。模式 `0x80` 支持键盘及相对鼠标。拾取和采矿共用该串口，通过 CH9329 发送右键按下和松开，鼠标位置不动。主窗口标题右侧显示键鼠连接状态，输入失败时界面会提示原因。

键盘测试前先将接收端的记事本切到英文输入。逐条运行以下命令，分别在三秒内把焦点切到记事本，或把鼠标指针移到记事本编辑区。记事本应收到一个 `q`，右键测试应弹出菜单。

~~~powershell
.\.venv-local\Scripts\python.exe input_check.py --test-q --trace
.\.venv-local\Scripts\python.exe input_check.py --test-mouse --trace
~~~

连接了多个 CH343 时，可用 `$env:CH9329_PORT = "COM7"` 在当前 PowerShell 会话内指定端口，助手和测试命令都会使用它。仅为某次测试指定端口时，可加 `--ch9329 COM7`。

- 串口能打开但没有有效应答时，确认板子处于 **协议传输模式**。默认设置是 **9600 / 8N1 / 地址 0x00**。如果已用厂商工具改成 115200，自检命令加 `--baud 115200`，主界面使用 `$env:CH9329_BAUD = "115200"`。自定义地址对应 `--address 0xNN` 或 `CH9329_ADDRESS`。
- 有芯片应答但 USB 未枚举时，检查 HID 端的数据线。芯片应答正常而目标没有反应时，核对 HID 接收端和前台焦点。
- [CH9329 模块](wow_assistant/device/ch9329.py) 封装了 `CH9329Keyboard`。调用方可把实例传给 `WindowsInput(keyboard=...)`，复用前台窗口检查和 `send()`，结束时调用 `close()`。所用报文与 [按键编码](docs/按键编码.txt) 和 [串口通信协议](docs/CH9329芯片串口通信协议.pdf) 对照，初始化查询不会写入芯片配置。

Pico 的键盘桥仍可供代码独立调用。主界面的自动功能要求 CH9329 键鼠设备。

## 战斗开关和技能配置排查

Windows 直接监听实体鼠标 5 和 F10 按下再松开的事件。开关无需 CH9329 参与，自动技能键和点击仍通过 CH9329。独立的 `diagnose_ctrl.py` 可只读排查鼠标 5 或 F10、前台窗口和技能配置。

不同技能框选到同一格时会明确报错，拒绝覆盖原图片和配置；启动时也会检查已保存坐标，防止错误配置持续发 Q。圣印应选第二格，神圣打击选第一格，审判选第四格；框选范围不要包含相邻图标。底部诊断显示技能状态/相似度及修饰键占用，窗口按字体和 DPI 预留显示空间。

### 目标框和血量

启动自动战斗并选中活怪后，助手会在游戏窗口右下区域定位目标框，并把相对窗口的位置保存到 [combat_config.json](config/combat_config.json)。以后直接读取已保存的位置。若自动定位失败，点击「目标框」并框住目标面板左侧的完整三行和左右边框即可，头像可留在框外。

首次确认红底活怪后放行 Q/E/R，满血目标也可以主动开打。之后目标死亡、消失或状态无法确认时进入 15 秒过渡期，普通攻击继续按原有就绪与冷却规则运行。15 秒内重新确认活怪就取消倒计时，连续失效满 15 秒才暂停。明确识别到绿底或黄底时立即拦住发键。助手尝试读取当前血量和总血量，数字不清晰时用血条长度估算。目标头像边框的金色和红色对应已选中和战斗中。

### 圣印舞

默认关闭。开启前在「圣印校验」里定位两个区域，已有结果会打勾并保存在 `combat_config.json`。

1. 开启命令或正义圣印，框住显示名称的插件进度条，确保包含左端图标。
2. 有储存图标时，框住左侧储存增益的一小排，让储存图标在变换位置时仍留在范围内。
命令和正义储存三层样本已内置。图标样式变化时，可用「正义储存三层图标」单独框选带 `3` 的正义图标更新样本。

确认处于战斗中、目标血量至少 20%，并且当前圣印的储存达到三层后，命令用主键区 `1` 切正义，正义用 `Q` 切命令。公共冷却挡住切印时，每隔约半秒最多发三次，每次发键前重新核对条件。检测到新圣印后结束重试。旧的三层图标即使残留，也只锁住它自己，另一种圣印三层仍可切换。血量接近 20% 且数字无法确认时等待清晰读数。没有活目标时保持暂停，在再次选中可确认的活目标后按状态补回默认的命令圣印。

没有活目标时，目标检测降到约每秒四次，圣印舞等重新确认活怪后再继续。15 秒过渡期结束后暂停攻击技能截图，V 净化继续单独检测。选中活怪但尚未交战时，低频检查当前圣印。有待确认的切印时，会额外复核旧储存图标。

## 悬停拾取与采矿

- **自动拾取**使用原分辨率视频提取的 [袋子模板](assets/loot_cursor.png)。指针稳定约 150 毫秒、点击前复核通过后，在当前位置右键一次。移开袋子指针约 0.4 秒，或移动超过 24 像素，可开始下一次悬停。拾取仍有 1 秒点击间隔保护。
- **自动采矿**使用原分辨率视频提取的 [矿镐模板](assets/mining_cursor.png)。识别到矿镐时暂停 Q/E/R。指针稳定后右键一次，随后每隔至少 4 秒复核并右键一次。矿镐消失后停止复点，持续约 0.4 秒后恢复攻击。V 净化照常运行。
- 程序先识别 Windows 系统指针，然后尝试鼠标附近的画面。透明模板只比较图案像素。系统指针分数的最低门槛为 50%，画面模板为 65%，并同时检查颜色。窗口焦点、鼠标位置、按键占用和点击前复核也会影响是否发送。
- 成功发送右键后，控制台会显示实际使用的鼠标后端。需要只采矿时，勾选“采矿”并取消其余两项，再按鼠标 5 或 F10。

## R 制裁

在游戏里把制裁绑到 R，等图标就绪且没有倒计时，再点助手的「制裁 (R)」框选完整图标。校验成功会保存图片和坐标。制裁就绪时优先发送 R，优先级高于审判和神圣打击。制裁在冷却或图标无法确认时，继续执行原来的 E 攻击规则。还没校验制裁时可照常使用原有技能。

## E/R 短连发

战斗技能栏的目标采样间隔为 25 毫秒。相邻的三个技能图标共用一张截图；相距较远或跨显示器时分别截图。

1. E 或 R 进入就绪时，约半秒内随机安排 2–3 次尝试，间隔略有变化。E 共用一次连发，制裁就绪时 R 仍优先。
2. 每次补发按最新的技能识别结果和当前目标状态判断。技能冷却或画面未知时取消后续补发。
3. 图标持续就绪但本轮未确认施放时，间隔至少 2 秒才开下一轮。短暂公共冷却恢复后可按最新图标及时继续。
4. 神圣打击保留 10 秒、审判保留 8 秒的冷却保护。Q 和圣印舞沿用各自的调度。

一个 E 能否同时放出两个技能由游戏内键位和公共冷却决定；工具通过短连发尽量及时补出剩下的技能，不能绕过游戏自身的施放限制。请保留你原来能使用两个技能的 E 绑定。

## V 中毒净化：首次校验后复用

已将提供的两张图片裁出图标主体，保存为 `poison_1.png` 和 `poison_2.png`。倒计时文字不参与模板比较。

1. 让自己处于上述任一种中毒状态，点击 **“减益栏 V”**，框选自己整排减益图标。两种毒不需要同时出现，不要框选技能栏或整个屏幕。
2. 必须实际匹配到其中一种图标才保存检测区域和图标尺寸；校验失败保留之前的有效配置。
3. 成功后保存到 `combat_config.json`，重启后直接复用。减益图标在该区域内换位置仍可识别；移动减益栏或改变 UI 缩放后重新校验。
4. 开启战斗后，目标检查间隔为 50 毫秒；发现任一种中毒即优先发送 **V**，随后让出约 1.5 秒公共冷却，再继续战斗。
5. V 发出后继续观察图标。图标连续消失至少 0.25 秒后记录已确认解除；仍中毒时每隔至少 1.6 秒复查重试，不刷屏连按。工具确认的是图标消失，未读取游戏内存。

请确保你的 V 绑定会对自己施放纯净术（按你已有的自身施法/宏配置）。工具只按 V，不改变施法目标或鼠标位置。未校验减益栏时不发送 V，原 Q/E 和拾取仍可运行。

扩展其他中毒图标时可在 [中毒识别模块](wow_assistant/vision/poison.py) 的 `POISON_TEMPLATES` 中追加 `assets/` 中的图标文件。识别使用纹理和颜色，纯绿色色块不会当作中毒。

界面主状态用绿色强调，净化提示用琥珀色，拾取与设置说明使用灰色；只展示计数和必要状态。

原有图片和坐标继续使用。你也可以自己截取完整图标，在 `assets/` 中保存或替换为以上文件名，重启后加载。图片应对应相同 UI 布局与缩放。

首次没有位置，或者移动了技能栏，才用三个“定位”按钮框选一次。定位会同时保存图片与 combat_config.json 中的屏幕坐标。**本地图片只描述图标长相，单靠它不能知道屏幕坐标**；本版不会自动全屏搜索技能位置。不要把整条技能栏、鼠标悬停高亮或冷却中的图标保存成就绪样本。

配置保存功能勾选、圣印匹配阈值、技能区域和减益栏的位置与尺寸。

## 安装（尚无虚拟环境时）

本机 Python 3.14 已验证。无需激活虚拟环境：

~~~powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

EasyOCR/PyTorch 体积较大。首次模型下载后复用用户目录中的 .EasyOCR 缓存。战斗截图和图标比较使用 MSS/OpenCV；主战斗流程不再加载红字 OCR。

## 保留的名称识别

~~~powershell
.\.venv\Scripts\python.exe monster_ocr.py --ocr
~~~

名称识别模式与攻击分别启动。名称识别区域和目标保存在 [config.json](config/config.json)，保存的截图位于 `diagnostics/`。
